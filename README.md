# Класс — платформа для репетиторства

Адрес: **https://tutor.baibakovkir.space**. Русский интерфейс, московское время (UTC+3), рубли.

## Возможности

- Общий недельный календарь преподавателя и фильтр по ученику. Разовые и еженедельные занятия на 2–24 недели, перенос и отмена, защита от пересечений, отметка проведения.
- Карточки учеников: предмет, контакт, стоимость занятия, ссылка на видеосвязь, личные заметки преподавателя, архивирование.
- Отдельный кабинет каждого ученика по персональной ссылке: только его расписание, оплаты, материалы, ДЗ и история ответов. Замена ссылки отзывает прежнюю и старые сеансы ученика.
- Статусы «Оплачено / Не оплачено» у каждого занятия. Суммы ожидаемых оплат и долга за прошедшие встречи. Это ручной учёт, без платёжного шлюза.
- Домашние задания со сроком, текстом, ссылками и файлами до 20 МБ каждый. Ученик отправляет ответ и прикладывает файлы; преподаватель оставляет комментарий, проверяет или возвращает на доработку.
- Библиотека: выбор ответа, короткий ответ с автопроверкой и развёрнутый ответ с ручной проверкой. Шесть стартовых заданий, создание своих и копирование готовых. Назначение заданий ученикам и история попыток.
- Ссылка на существующий SQL-тренажёр. Видеосвязь открывается во внешнем сервисе по вашей ссылке.

На production нет демонстрационных учеников и фиктивных оплат. Добавьте первого ученика, создайте занятия и отправьте ссылку из карточки ученика. Сохраните созданную ссылку: в базе хранится только её SHA-256, повторно прочитать её нельзя. Следующее нажатие создаёт новую ссылку и отзывает старую. Кабинет ученика работает без отдельного пароля; относитесь к ссылке как к ключу доступа.

Доработка находится в этом репозитории вместо отдельного GitHub fork: сохранены MIT-лицензия, исходный README и атрибуция. Использованы модели и миграции MyClass, авторизация, функции календаря. Старые интерфейс и API заменены русскими кабинетами; добавлены учебные функции, защита файлов, переносы, проверка конфликтов и эксплуатация. Next.js и Auth.js обновлены до исправленных версий.

## Локальный запуск

Для локальной разработки нужны Node.js 24, npm и Docker Compose.

```bash
npm ci --cache /tmp/tutor-npm-cache
cp .env.example .env
# Замените AUTH_SECRET случайной строкой; POSTGRES_PASSWORD и DATABASE_URL должны совпадать.
docker compose up -d --wait
npm run db:migrate
npm run set-password -- you@example.com 'your-strong-password' 'Ваше имя'
npm run dev
```

Адрес http://localhost:3000 должен совпадать с `AUTH_URL`. Для локальной работы используйте localhost. Production cookie ученика передаётся по HTTPS.

## Размещение на сервере

Выбран **SSH + готовая standalone-сборка + systemd**, база в отдельном Docker volume. Сборка выполняется локально, на сервер отправляется около 70 МБ готового приложения. Это экономнее по месту и памяти, чем новая многослойная сборка Node-образа на небольшом сервере. Существующие сервисы не затрагиваются.

```bash
bash ops/deploy.sh
```

По умолчанию используется `user@176.123.163.174` (переопределение `TUTOR_TARGET`). `ssh -F /dev/null` обходит некорректные права системного include SSH в текущем окружении. Ключи и проверка known_hosts остаются штатными.

- Каталог: `/home/user/tutor-platform`; релизы: `releases/<UTC timestamp>`, ссылка `current`.
- Приложение: systemd `tutor-platform.service`, только `127.0.0.1:13003`.
- База: Docker Compose `tutor-platform`, PostgreSQL 17, только `127.0.0.1:15440`, volume `tutor-platform_pgdata`.
- Файлы: `/home/user/tutor-platform/storage/uploads`. Файлы не публикуются nginx; загрузка через API с проверкой доступа.
- Секреты: `/home/user/tutor-platform/.env`, права 600. Они создаются на сервере, не входят в архив приложения и Git.
- Первые реквизиты: `/home/user/tutor-platform/access.txt`, права 600. При обновлениях пароль не сбрасывается. После первого входа смените его в настройках; смена отзывает старые сеансы преподавателя.
- Nginx: `/etc/nginx/conf.d/tutor-platform.conf`. Отдельный сертификат Certbot, webroot `/var/www/tutor-acme`, HTTP → HTTPS, hook перезагрузки nginx после продления.
- Проверка: `GET /api/healthz` проверяет подключение к базе и наличие схемы. Неудачная проверка после перезапуска возвращает ссылку на предыдущий релиз.

Обновление не удаляет старые релизы автоматически. Они небольшие; после успешной проверки можно вручную удалить ненужные, оставив текущий и предыдущий. Не выполняйте `docker compose down -v`: это удаляет данные.

## Бэкапы и восстановление

Таймер `tutor-platform-backup.timer` запускает `ops/backup.sh` ежедневно в 03:40 UTC. Бэкап также создаётся перед обновлением: PostgreSQL custom dump, файлы, runtime env, путь релиза. Каталог `/home/user/tutor-platform/backups/<timestamp>`, права закрыты umask 077; завершённые копии старше 14 дней удаляются. Копии находятся на том же сервере — для защиты от потери сервера нужно дополнительно выносить их на другое хранилище.

Ручной запуск и проверка:

```bash
ssh -F /dev/null user@176.123.163.174 'bash /home/user/tutor-platform/ops/backup.sh'
ssh -F /dev/null user@176.123.163.174 'systemctl status tutor-platform; systemctl list-timers tutor-platform-backup.timer'
```

Откат приложения: переключить `current` на предыдущий релиз и перезапустить сервис. Миграции текущего релиза добавляют таблицы; они совместимы с предыдущей версией. Для восстановления данных сначала остановите сервис, сохраните текущие данные, затем восстановите выбранный dump через `pg_restore --clean --if-exists --no-owner -U tutor -d tutor` внутри контейнера и распакуйте соответствующий `files.tar.gz` в `storage`. Запустите сервис и проверьте health endpoint. Не восстанавливайте базу поверх работающего приложения.

## Проверки

GitHub Actions запускает тесты, сборку, упаковку standalone-релиза и интеграционные сценарии с отдельной PostgreSQL. Публикация выполняется вручную по SSH.

```bash
npm run typecheck
npm test
npm run build
# Отдельная локальная тестовая БД и запущенное приложение, переменные из .env:
node --env-file=.env tests/integration.mjs
```

Интеграционные проверки создают двух временных преподавателей, после тестов удаляют только их данные. Внешние production URL запрещены. Проверяются вход, права преподавателей и учеников, пересечения и атомарность повторяющихся занятий, конкурентная запись, оплаты, ДЗ, автопроверка, комментарии, приватные файлы, CSRF, отзыв ссылок и архивирование. Для браузерных проверок задайте `PLAYWRIGHT_MODULE` и при необходимости `PLAYWRIGHT_EXECUTABLE_PATH`; проверяются вход, создание ученика, копирование шаблона, мобильный интерфейс и кабинет ученика. Скриншоты находятся в игнорируемом `artifacts/`.

Индивидуальные ДЗ и совместные игровые занятия используют отдельные интерфейсы: обычные задания назначаются на дом, игры запускаются в общей комнате.

## Совместные игровые занятия

Откройте «Игровые занятия» в кабинете, выберите раздел учебника и нажмите «Играть». Выберите ученика, механику и режим; ученик увидит приглашение в своём кабинете. Запуск из карточки занятия сохраняет привязку к встрече. Кнопка игр в карточке ученика открывает его игры и историю.

Доступны мемори «Найди пару», сборка фразы, гонка с движущимися фишками, викторина/дуэль и приключение по пяти локациям. Режимы: преподаватель-ведущий, совместная игра с общим счётом, дуэль. Приключение поддерживает ведущего и совместное прохождение. Для каждой локации можно выбрать свой набор — например, соединить лексику GoGetter и грамматику Essential.

При сборке фразы слова можно перетаскивать или выбирать нажатием. Нажатие на выбранное слово возвращает его в запас; стрелки влево/вправо на сфокусированном выбранном слове меняют порядок. Карточки открываются и закрываются синхронно. В дуэли ответы и начисленные очки скрыты до завершения раунда обоими участниками. Таймер по умолчанию выключен; доступны 30, 60 и 120 секунд. Таймер проверяется сервером и останавливается на паузе. После разрыва соединения поле восстанавливается из базы, во время переподключения ходы отключены.

В библиотеке 124 тематических набора: GoGetter 3 с Workbook (9 разделов) и Essential Grammar in Use 4th edition (115 разделов). Объём и устройство авторских упражнений описаны в [content/games/README.md](content/games/README.md). Advanced остаётся на следующий этап. Папка `books/` не публикуется.

Копируйте готовые наборы или создавайте свои в редакторе: пары, фразы и вопросы с вариантами. Активная игра использует зафиксированную копию заданий. История сохраняет ответы, ошибки, пропуски и подсказки. Из ошибок завершённой игры можно подготовить новый набор, если в ней хотя бы два разных задания для повторения.

Игры используют отдельные таблицы `game_sets` и `game_rooms`; состояние, принятые команды и результаты сохраняются транзакционно. Обновления приходят через SSE, повтор команды с тем же идентификатором не начисляет очки второй раз. Сервер проверяет владельца, ученика и правила хода; правильные ответы, закрытые карточки и порядок слов не кодируются в публичных идентификаторах. Доступ отозванного или архивированного ученика закрывается и для игрового соединения. SSE не требует дополнительного сервиса или Redis. Выборка интерфейса показывает до 100 последних игр с сохранением всей истории в базе.

Перед обновлением выполняется существующий бэкап. Миграция `0010-games.ts` только добавляет таблицы и не меняет данные расписания, оплат и домашних заданий. Бэкапы базы включают пользовательские наборы и игровые комнаты; стартовый банк входит в версию приложения. Откат приложения на предыдущий релиз сохраняет новые таблицы и результаты.

Проверка готового standalone-релиза: после `node ops/package.mjs` скопировать `.release` в отдельный каталог вне проекта и выполнить `node --env-file=.env tests/standalone.mjs /tmp/tutor-package-check`. Этот сценарий запускает сервер, выполняет интеграционные проверки, перезапускает процесс с незавершённой игрой и проверяет восстановление результатов и доступа участников. При заданном `PLAYWRIGHT_MODULE` дополнительно проверяет все пять игровых форматов в двух независимых браузерах. GitHub Actions запускает проверки API и перезапуска на упакованном релизе.
